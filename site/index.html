SEE HOW A RUN WORKS, STEP BY STEP

You answer questions once. Then it’s hands-off.

Questions from the agents go to the coordinator. It answers from the spec, or decides and logs an assumption for you to review. A repo coordinator passes up any question that changes a contract or the Shared approach.

  1. 1WITH YOU

    Grill

    The coordinator interviews you, suggests repos from repos.json, confirms build and test commands and asks for unset extension settings. It proposes one child per repo, package or page, and shows maxParallel so you can change it.

  2. 2WITH YOU

    Spec

    It writes spec.md: goal, children, contracts, ordering, acceptance criteria and a Shared approach that every plan must follow. One last question, “anything to change?”, and your answer starts the run.

  3. 3HANDS-OFF

    Plan gate

    Every planner runs at once, read-only. Before any code changes, the coordinator checks each plan against the Shared approach and against the other plans, and sends a plan that doesn’t fit back.

  4. 4HANDS-OFF

    Baseline tests

    Optional. A baseline agent writes tests, for example Playwright, that pass on the unchanged code. The tester fails any edit to them that the spec doesn’t list, so the new code has to keep the old behaviour.

  5. 5HANDS-OFF

    Build and test

    Each child implements and tests in dependency order, in its own worktree and port range. A failing test gets up to 3 retries, then one guided attempt by the coordinator.

  6. 6YOUR REVIEW

    Finish

    A repo with several children gets a repo coordinator. It merges them into one integration branch and runs the full build and tests. Then you get the changes staged, or one draft PR per repo that links to the others.

One agent per page. One PR per repo.

Split a repo into children by page, module or unit, each limited to its own paths. A setup child adds shared code first. A repo coordinator merges the children into one integration branch, has a child’s own implementer fix a merge conflict, and runs the full build and tests before the repo’s PR.

npx openfleet scope <project> <child> --check

Sized for your machine.

maxParallel caps how many agents work at once across every run, 6 by default. Each child gets its own range of ports, and files like .env.local are copied into its worktree but never committed.

npx openfleet config set maxParallel 4

Shared contracts keep repos in step.

The coordinator writes shared fixtures, and every repo’s contract tests run against them. A contract change is broadcast to the children it affects.

Three commands to your first fleet.

You need Node.js 20+, git and a signed-in coding agent CLI. Add gh if you want draft PRs. To try it on a toy example first, run pnpm demo from a checkout of the repo.

Know what it can touch. Tools are auto-approved, but file access stays limited to the workspace and your repos, and URLs still prompt. Pass --ask for per-tool prompts.

Extend any step of the run.

Install an extension with openfleet add. It can run as its own agent at a phase slot, add to a role’s instructions, or add CLI commands. It is instructions only, with no code. Write and shell access must be declared, and the tool allow-list enforces it.

READ THE EXTENSION GUIDE
  • pre-spec
    During the grillRuns once, before the coordinator writes spec.md.
  • post-planCAN BLOCK
    After each plan is validatedRuns per child, for example to review a plan against team rules.
  • plans-readyCAN BLOCK
    At the plan gateRuns once, after every plan passed the consistency check and before anything is implemented.
  • pre-implementCAN BLOCK
    Before each implementerRuns per child, after the gate and its baseline tests.
  • post-testCAN BLOCK
    After tests passRuns per child. The child is done only when these finish, so dependents wait for them.
  • post-run
    When the run finishesFor example, an audit that summarises the run from events.jsonl.
  • Blocking A failed blocking entry gets one retry with a fresh agent. If that fails too, the child fails and the children that depend on it are blocked.
  • Only when it applies With when.files, an entry runs only in repos that have one of the files, and is logged as skipped elsewhere.
  • Outputs for dependents A report can return outputs, such as a published version. Every dependent child’s planner, baseline, implementer and tester gets them as “Upstream outputs”. A prUrl output makes finalize update that PR instead of opening a new one.
  • Settings, asked once Settings are workspace-wide. The grill asks about any without a value, and npx openfleet ext settings lists them.
