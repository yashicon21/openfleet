HOW IT WORKS · AN EXAMPLE RUN

Seven repos, 23 agents, 4:40

One prompt: rename user_id to account_id in the API, both SDKs and every client. This page walks through the run event by event: who did what, to which repo, and when.

This run is illustrative: the timings and events are mocked, but every event type is one OpenFleet really logs. For a real run you can replay yourself, try pnpm demo.

01 · THE WHOLE RUNUnder five minutes, 23 agents

OpenFleet writes every step of a run to events.jsonl: who did what, to which repo, and when. The coordinator is the agent you talk to. It spends the first forty seconds with you, settling questions and writing a spec. After you approve, it creates a worktree for each repo and hands each one to three short-lived sub-agents in turn: a planner, an implementer and a tester.

Press replay to watch all 203 events land. Six repos start within ten seconds of each other. mobile sits idle until sdk-js is done, because the spec ordered it that way.

02 · STATEEvery repo walks the same path

The coordinator moves each repo through the same phases, and almost always forwards. The one exception is sdk-python: after a failed test it goes back from testing to implementing (the ↺), with the tester’s findings attached. mobile spends most of the run in pending, waiting on sdk-js.

03 · MESSAGESThe coordinator talks, agents report back

Sub-agents never talk to each other. Each one gets a single instruction from the coordinator, does its job in that repo’s git worktree, and ends with a structured openfleet-report: a status, a summary and, if it has one, a question. Twenty-three instructions out, twenty-three reports back, plus the spec handoff with you at the start.

04 · THE CODE314 lines across 24 files

Most of the diff is renames and tests. The api adds a migration and a contract test; the SDKs note the breaking change in their changelogs. sdk-python’s second implementer adds the deprecated alias and one test for it.

05 · THE DECISIONSA contract change, a retry and an assumption

Most of a run is agents working alone. The interesting moments are where the coordinator has to step in: answering a question, sending a repo back after a failed test, or making a call the spec didn’t cover. Step through the four that shaped this run.

06 · VERIFY177 tests, one retry

Each tester runs the repo’s own test command. Contract tests, in blue, check every consuming repo against the same rows in account.json. Press run to replay them: sdk-python fails one test, gets a fresh implementer, and passes on the retry.

07 · WHAT’S LEFTSeven draft PRs, linked

The run ends in draft PR mode, as agreed in the grill. The coordinator commits each worktree to its openfleet/account-id branch, pushes it and opens a draft PR. Every PR links to the other six and carries the run summary, which lists the one assumption for you to confirm. Nothing merges until you do.

Want to look before anything leaves your machine? Choose staged in the grill instead, and the changes wait uncommitted in each worktree.
